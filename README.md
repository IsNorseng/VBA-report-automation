# Автоматизация ежедневной строительной отчётности на VBA

Практический пример из моей работы в АО «Системы Управления». Я автоматизировал обновление Excel-таблиц для ежедневной строительной отчётности: данные поступали от инженеров, затем сводились в отчёт и использовались в презентации.

**Инструменты:** Microsoft Excel, VBA, формулы R1C1, ВПР / VLOOKUP.

## Задача

Отчёт включал около десяти таблиц с разными показателями. При ежедневном обновлении приходилось менять ссылки на исходные файлы, вставлять и протягивать формулы. Имена файлов следовали одному шаблону и менялись вместе с датой отчёта.

Задача автоматизации — перенести повторяющиеся операции в макрос и сократить ручную работу при подготовке сводных таблиц.

## Состав репозитория

| Файл | Содержание |
| --- | --- |
| [Macros](Macros) | Исходный пример макроса `Макрос1`: подстановка даты в ссылки, запись формул, автозаполнение диапазонов. Названия листов и источников заменены шаблонными значениями. |
| [Macros_v2](Macros_v2) | Структурированная версия с процедурой `UpdateReport`, настройками, вспомогательными функциями, проверками файлов и обработкой ошибок. |

Оба файла — текст VBA без расширения. Готовой книги `.xlsm`, исходных Excel-таблиц и презентации в репозитории нет. Для воспроизведения нужно подготовить собственную книгу и данные с подходящей структурой.

## Мой вклад и принцип работы

Я перенёс повторяющиеся действия из ручной подготовки отчёта в VBA: использовал запись макроса, добавил переменную даты, настроил ссылки на источники и заполнение формул.

1. Дата из ячейки отчёта становится частью имени исходного файла.
2. Макрос записывает внешние ссылки в заданные ячейки сводных таблиц.
3. Для детализации используются `VLOOKUP` и `IFERROR`, для итогов — формулы суммирования и разности.
4. После обновления выполняется переход на лист с диаграммами.

В `Macros_v2` настройки собраны в константы, обращения к книге привязаны к `ThisWorkbook`, а повторяющиеся операции вынесены в процедуры. Эта версия представлена как развитие примера; отдельный эффект её применения в рабочем процессе не измерялся.

Сбор исходных файлов, проверка результата, подготовка скриншотов и визуальное оформление отчёта оставались ручными. Код не автоматизирует создание презентации или снимков экрана.

## Результат

По моей оценке, основанной на рабочем опыте, подготовка и обновление таблиц сократились с нескольких часов до минут. Это личная оценка времени, а не результат формального замера. Основной результат — автоматизация повторяющегося переноса данных и формул в ежедневной отчётности.

## Как адаптировать и запустить

Потребуется настольный Microsoft Excel для Windows с поддержкой VBA. Отдельные библиотеки в коде не подключаются; версия Excel в репозитории не зафиксирована.

1. Создайте копию своей отчётной книги и сохраните её в формате `.xlsm`.
2. Откройте редактор VBA (`Alt+F11`), добавьте стандартный модуль и вставьте содержимое [Macros_v2](Macros_v2).
3. Укажите каталог источников, префиксы имён файлов, названия листов и формат даты в блоке настроек. Подготовьте два исходных файла `.xlsx`, на которые ссылается пример.
4. Сопоставьте адреса ячеек, диапазоны и ключи поиска со своей структурой данных. Одной замены имён файлов недостаточно, если расположение таблиц отличается.
5. Запишите дату в настроенную ячейку; по умолчанию это `Параметры!B1`.
6. Разрешите выполнение проверенного макроса и запустите `UpdateReport`. Сверьте заполненные таблицы с источниками.

## Ограничения

- Код привязан к определённой структуре листов и диапазонов; это пример автоматизации конкретного отчёта.
- Проверки наличия файлов и листов в `Macros_v2` не проверяют достоверность исходных показателей.
- `IFERROR(..., 0)` заменяет ошибки поиска нулём, поэтому нулевые значения требуют сверки с источником.
- Исходная версия зависит от активного листа и содержит записанные действия интерфейса.
- Без отчётной книги и исходных таблиц полный запуск из репозитория невозможен. Макросы при подготовке этого описания не выполнялись.
